## 2. Хостинг — переехали с Netlify на Vercel

На Netlify кончились кредиты бесплатного тарифа, и он начал отклонять любую
сборку: `Skipped due to account credit usage exceeded`. Блокировались оба пути —
и автосборка из GitHub, и выкладка локальной сборки. Ограничение аккаунта, не
проекта, поэтому чинилось только деньгами или ожиданием 11.09.2026.

Заказчик выбрал переезд на Vercel — это разработчик Next.js, бесплатный тариф
щедрее, плагин-адаптер не нужен.

**Что изменилось в коде:** заголовки безопасности и кэш для `/brand` и
`/images` переехали из `netlify.toml` в `next.config.ts`. Это важнее, чем
кажется: в конфиге хостинга они бы потерялись при переезде молча, без единой
ошибки в сборке. Сам `netlify.toml` и `@netlify/plugin-nextjs` удалены —
Vercel определяет Next.js без конфига.

**Автодеплой подключён:** `git push` в `main` сам пересобирает сайт.
Подключение делается только через веб-интерфейс — из CLI `vercel git connect`
возвращает `Failed to connect`, пока приложение Vercel не установлено в
GitHub-аккаунт. Инструкция в `DEPLOY.md`, раздел «Вариант 2».

**Старый сайт на Netlify** отвечает 200 и показывает устаревшую версию. Его
стоит удалить, чтобы не расходились две копии; я этого не делал без спроса.

## 3. Что сделано

Многостраничный магазин на Next.js 16 (App Router) + React 19 + TypeScript +
Tailwind CSS v4. Сборка проходит: 0 ошибок TypeScript, 0 ошибок ESLint,
**32 e2e-теста Playwright** зелёные на desktop и mobile.

Реализованы: главная с каруселью баннеров, каталог с фильтрами и сортировкой,
страница товара, поиск, избранное, корзина, промокоды, оформление заказа с
выбором перевозчика, накладная, письма, страницы «О нас», «Отзывы»,
«Оплата и доставка», «Контакты», «Политика», 404, sitemap и robots.

### Отклонения от протокола (зафиксированы осознанно)

**Интервью не проводилось в полном объёме.** `clode.md` требует структурированного
интервью до проектирования. Заказчик передал детальное ТЗ (`Electric_Fireplaces.md`,
81 раздел) и бриф, и команду начинать. Задано три уточняющих вопроса (цены, бренд,
конфликт названий Версаль/Верона) — ответы учтены.

**Видео огня в hero заменено CSS-анимацией.** ТЗ (п.13) просит видео. В материалах
его нет. Пламя на реальном фото горящего очага оживляется четырьмя CSS-слоями.
Слот под видео готов: `heroMedia.video` в `src/config/site.ts`.

## 6. Дизайн-система

Токены — CSS-переменные в `src/app/globals.css` (`@theme`). HEX по компонентам
не разбросан.

| Токен                                | Значение              | Роль                             |
| ------------------------------------ | --------------------- | -------------------------------- |
| `--color-primary`                    | `#e97821`             | CTA, акценты, активные состояния |
| `--color-primary-hover` / `-active`  | `#d2650f` / `#b95709` | состояния кнопок                 |
| `--color-primary-soft`               | `#fdefe1`             | подложки акцентов                |
| `--color-brand-red` / `-grey`        | `#a23131` / `#9b9b9b` | цвета логотипа                   |
| `--color-canvas` / `--color-surface` | `#ffffff` / `#fbf8f4` | фон / чередующиеся секции        |
| `--color-ink` / `--color-ink-soft`   | `#1c1917` / `#57534e` | текст / вторичный текст          |
| `--color-line` / `-strong`           | `#e9e2d8` / `#d8cec0` | разделители / рамки полей        |

Шрифт — **Manrope** (400–800) через `next/font/google` с кириллицей.
Контейнер 1320 px, отступы 16/24/40 px.

Свои классы вместо системных контролов: `.ef-checkbox` (белая галочка на оранжевом,
системный `accent-color` рисовал тёмную), `.ef-select` (стрелка с отступом 12 px
от края), `.ef-radio`.

**Иконки — все «от руки».** Геометрия (lucide для интерфейса, свои контуры для
информационных блоков) прогоняется через rough.js скриптом
`scripts/make-sketch-icons.mjs` → `npm run icons`. В браузер уезжают готовые
пути, библиотека остаётся на этапе сборки. Подробности и параметры — в
`README.md`, раздел «Иконки». `lucide-react` переведена в devDependencies и
закреплена на 0.469: в 1.x структура пакета другая и разбор сломается.

## 7. Ключевые решения

**Типографика.** `src/lib/typography.ts` — функция `typo()` расставляет неразрывные
пробелы: короткие предлоги и союзы, число с единицей измерения, тире с предыдущим
словом. Применяется на уровне данных каталога и внутри переиспользуемых
компонентов. Проверено: ноль висячих предлогов на 12 страницах × 6 брейкпоинтах.

**Изображения.** Двухступенчатый конвейер:

1. `scripts/prepare-images.mjs <путь к архиву>` — отбор по `scripts/image-manifest.json`,
   конвертация в WebP, единые пропорции (товары 3:4);
2. `scripts/make-covers.mjs` — производные кадры из готовых WebP: обложки категорий
   (`COVERS`), баннеры карусели (`PROMOS`), кадры блока производства (`PRODUCTION`)
   и главные фото карточек (`CARDS`). Второй скрипт работает без исходного архива.

У четырёх моделей (Честер, Мальта угловая, Верона, Мальта венге) среди исходников
нет ни одного кадра без маркетплейс-надписей — для них `CARDS` вырезает середину
кадра. Границы текстовых полос выверены по каждому фото отдельно.

**Доставка.** Два перевозчика в `src/config/site.ts` → `carriers`: СДЭК (`primary`)
и «Деловые Линии». API считает обе разом, покупатель выбирает при оформлении.
Провайдеры: `mock-provider` (демо-формула), `cdek-provider`, `dellin-provider` —
подключаются независимо через переменные окружения.

**Хранилище заказов.** `src/lib/orders/store.ts` — интерфейс `OrderStore` с
реализацией в памяти. На serverless история не накапливается (функции не делят
память): заказ создаётся, письма уходят, накладная показывается, но выдать старый
заказ по номеру нельзя. Под историю нужен класс с `save`/`find` в `getOrderStore()`.

## 8. Данные, требующие подтверждения заказчиком

Всё перечислено в README, раздел «Данные, которые требуют подтверждения». Кратко:

- **Цены** — прайса в материалах нет. Демо-значения в `src/data/prices.ts`.
- **Контакты и реквизиты** — заглушки в `src/config/site.ts`.
- **Способы оплаты** — не указаны, на `/delivery` нейтральный текст с пометкой.
- **Отзывы** — реальных нет, три демо-карточки с флагом `demo: true`.
- **Версаль / Верона** — по решению заказчика разведены как две модели.
- **Честер** — ТВ до 65″ (описание) против 75″ (инфографика); взято из описания.
- **Мощность** — 750/1500 Вт (описания) против 900/1500 Вт (одна инфографика).
- **Модерн, Дублин Премиум** — описаний нет, характеристики собраны по фото.
- **Вес изделий** — не указан, для доставки оценивается по габаритам.
- **Фотографии цеха** — отсутствуют, стоят честные заглушки `PlaceholderImage`.
