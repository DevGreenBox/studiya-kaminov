# Деплой на Netlify — пошагово

Инструкция рассчитана на того, кто делает это впервые. Ничего знать заранее не
нужно, всё по шагам.

Сайт уже развёрнут и открыт:

| Что | Где |
|---|---|
| Сайт | **https://studiya-kaminov.netlify.app** |
| Панель Netlify | https://app.netlify.com/projects/studiya-kaminov |
| Репозиторий | https://github.com/DevGreenBox/studiya-kaminov (приватный) |

Репозиторий подключён к Netlify: каждый `git push` в ветку `main`

Переменная `NEXT_PUBLIC_SITE_URL` уже задана — `sitemap.xml`, `robots.txt` и
мета-теги ссылаются на боевой домен.

Разделы ниже нужны, если сайт понадобится развернуть заново, перенести на
другой аккаунт или подключить домен и боевые интеграции.

## Что уже готово в проекте

* `netlify.toml` — команда сборки, папка публикации, версия Node и заголовки
  безопасности. Ничего вводить руками при подключении не придётся.
* `@netlify/plugin-nextjs` — официальный Next.js Runtime от Netlify. Нужен
  потому, что сайт не статический: у него есть серверные API-роуты (расчёт
  доставки, заявка продавцу, создание заказа).
* `.nvmrc` — фиксирует Node 22.

## Вариант 1. Через GitHub — рекомендуемый

Так каждый `git push` будет автоматически пересобирать сайт.

### Шаг 1. Положить код на GitHub

```bash
cd Electric_Fireplaces
git init -b main            # если репозиторий ещё не создан
git add -A
git commit -m "Сайт «Студия каминов»"
gh repo create studiya-kaminov --private --source=. --push
```

Если `gh` не установлен — создайте репозиторий вручную на github.com и выполните:

```bash
git remote add origin https://github.com/ВАШ_ЛОГИН/studiya-kaminov.git
git push -u origin main
```

### Шаг 2. Создать сайт на Netlify

1. Откройте **https://app.netlify.com** и войдите. Удобнее сразу кнопкой
   **Log in with GitHub** — тогда доступ к репозиториям выдастся автоматически.
2. Нажмите **Add new site** → **Import an existing project**.
3. Выберите **Deploy with GitHub**. При первом входе нажмите
   **Authorize Netlify**.
4. Если нужного репозитория нет в списке — нажмите
   **Configure the Netlify app on GitHub** и дайте доступ к `studiya-kaminov`.
5. Выберите репозиторий **studiya-kaminov**.
6. **Ничего не меняйте** на экране настроек: команда сборки, папка публикации и
   версия Node уже заданы в `netlify.toml`. Нажмите **Deploy**.

Первая сборка занимает 2–4 минуты. После неё Netlify выдаст адрес вида
`https://случайное-имя.netlify.app`.

### Шаг 3. Указать адрес сайта

Это обязательный шаг. Без него ссылки `canonical`, OpenGraph и `sitemap.xml`
будут указывать на `localhost`, и поисковики проиндексируют сайт неправильно.

1. **Site configuration** → **Environment variables** → **Add a variable**.
2. Ключ: `NEXT_PUBLIC_SITE_URL`
3. Значение: адрес из шага 2, например `https://studiya-kaminov.netlify.app`
   (без слэша на конце).
4. Сохраните.

### Шаг 4. Пересобрать

**Deploys** → **Trigger deploy** → **Clear cache and deploy site**.

Пересборка нужна, чтобы адрес попал в `sitemap.xml`, `robots.txt` и мета-теги.

## Вариант 2. Через командную строку — без GitHub

Подходит, если нужно быстро показать сайт заказчику.

```bash
npm i -g netlify-cli
netlify login                       # откроется браузер, подтвердите вход
cd Electric_Fireplaces
netlify init                        # «Create & configure a new site»
netlify env:set NEXT_PUBLIC_SITE_URL https://ВАШ-АДРЕС.netlify.app
netlify deploy --build              # черновик: даст превью-ссылку
netlify deploy --build --prod       # публикация на боевой адрес
```

Разница между командами: `netlify deploy --build` выкладывает черновую версию по
временной ссылке — её можно показать и проверить. `--prod` публикует на основной
адрес сайта.

## Переменные окружения

Обязательная одна:

| Переменная | Значение | Зачем |
|---|---|---|
| `NEXT_PUBLIC_SITE_URL` | `https://ваш-адрес.netlify.app` | canonical, OpenGraph, `sitemap.xml` |

Остальные добавляются, когда заказчик передаст доступы. Пока их нет, сайт
работает на демонстрационных провайдерах и честно сообщает об этом в интерфейсе.

**Доставка «Деловые Линии»:**

| Переменная | Значение |
|---|---|
| `DELIVERY_PROVIDER` | `dellin` |
| `DELLIN_API_URL` | `https://api.dellin.ru` |
| `DELLIN_APP_KEY` | ключ из личного кабинета |
| `DELLIN_SESSION_ID` | идентификатор сессии |
| `DELIVERY_ORIGIN_CITY` | город отправления, например `Москва` |

**Письма:**

| Переменная | Значение |
|---|---|
| `EMAIL_TRANSPORT` | `smtp` |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASSWORD` | доступы почты |
| `EMAIL_FROM` | адрес отправителя |
| `EMAIL_SHOP` | куда приходят заказы и заявки |

Перед включением `EMAIL_TRANSPORT=smtp` нужно доустановить `nodemailer` и
раскомментировать отправку в `src/lib/notifications/email/smtp-transport.ts` —
подробности в `README.md`.

> Ключи задаются **только** в панели Netlify. В репозиторий `.env.local` не
> коммитится, во frontend-бандл секреты не попадают.

## Что проверить после первого деплоя

1. Открыть `/` — логотип, фотографии и анимация огня на первом экране.
2. Открыть `/catalog?category=uglovye` — фильтр должен примениться сразу из URL.
3. Открыть `/sitemap.xml` — внутри должен быть боевой домен, а не `localhost`.
   Если `localhost` — значит не задан `NEXT_PUBLIC_SITE_URL` или не была
   сделана пересборка.
4. Открыть `/robots.txt` — там же должен быть боевой домен.
5. Добавить товар в корзину, применить промокод `FIRE10`, рассчитать доставку и
   оформить тестовый заказ — до страницы `/order/success` с накладной.

## Защита сайта паролем

На аккаунте Netlify была включена SSO-защита — она закрывала все сайты за
формой входа (HTTP 401). Для этого сайта она снята, поэтому он открывается
всем без пароля.

Если сайт снова начнёт спрашивать логин Netlify:
**Site configuration** → **Access & security** → **Visitor access** →
убрать защиту. Обратная операция там же, если нужно временно закрыть сайт от
посторонних до сдачи заказчику.

## Ограничение на бесплатном хостинге

Заказы сохраняются в памяти серверной функции (`src/lib/orders/store.ts`).
На Netlify функции живут недолго и не делят память между собой, поэтому
**история заказов не накапливается**: заказ создаётся, письма уходят,
покупатель видит страницу успеха и накладную — но получить старый заказ по
номеру через сервер нельзя.

Для демонстрации и передачи заказчику этого достаточно. Когда понадобится
история — подключите базу или CRM: нужно написать один класс с методами `save`
и `find` и вернуть его из `getOrderStore()`. Остальной код менять не придётся.

## Свой домен

**Site configuration** → **Domain management** → **Add a domain**.
Netlify покажет, какие DNS-записи прописать у регистратора, и сам выпустит
бесплатный SSL-сертификат.

После подключения домена не забудьте поменять `NEXT_PUBLIC_SITE_URL` на новый
адрес и снова сделать **Clear cache and deploy site**.

## Если сборка упала

1. **Deploys** → нажать на неудачный деплой → **Deploy log**.
2. Частые причины:
   * не установлены зависимости — проверьте, что `package-lock.json` в
     репозитории;
   * ошибка типов или линтера — воспроизводится локально командами
     `npm run typecheck` и `npm run lint`;
   * нехватка памяти на больших сборках — в
     `[build.environment]` добавить `NODE_OPTIONS = "--max-old-space-size=4096"`.
3. Локальная проверка ровно той же сборки:

```bash
npm ci
npm run build
npx next start
```

## Проверка боевого сайта тестами

Тесты можно прогнать не по локальной сборке, а прямо по развёрнутому адресу:

```bash
E2E_BASE_URL=https://studiya-kaminov.netlify.app npm run test:e2e
```

Это самая надёжная проверка после деплоя: она проходит весь путь покупки —
каталог, фильтры, поиск, избранное, корзина, промокод, расчёт доставки,
оформление заказа и накладную.
