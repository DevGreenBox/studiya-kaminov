# Деплой на Vercel — пошагово

Инструкция рассчитана на того, кто делает это впервые. Ничего знать заранее не
нужно, всё по шагам.

---

## Текущее состояние

Сайт развёрнут и открыт:

| Что | Где |
|---|---|
| Сайт | **https://studiya-kaminov.vercel.app** |
| Панель Vercel | https://vercel.com/devgreenbox/studiya-kaminov |
| Репозиторий | https://github.com/DevGreenBox/studiya-kaminov (публичный) |

Переменная `NEXT_PUBLIC_SITE_URL` задана — `sitemap.xml`, `robots.txt` и
мета-теги ссылаются на боевой домен.

> **Автодеплой из GitHub пока не подключён.** Приложение Vercel не установлено
> в аккаунт `DevGreenBox`, поэтому `git push` сам по себе сайт не пересобирает.
> Как это включить — раздел «Автодеплой из GitHub» ниже. Пока не включено,
> публикация делается одной командой: `npx vercel deploy --prod`.

---

## Почему Vercel

Раньше сайт жил на Netlify. Бесплатные кредиты аккаунта закончились, и
Netlify начал отклонять любую сборку с ошибкой
`Skipped due to account credit usage exceeded`. Vercel — компания, которая
разрабатывает Next.js, поэтому её бесплатный тариф к Next.js заметно
щедрее и никакого плагина-адаптера не требует.

Прежний адрес `studiya-kaminov.netlify.app` ещё открывается, но показывает
**устаревшую версию** и больше не обновляется. Его стоит удалить в панели
Netlify, чтобы не расходились две копии сайта.

---

## Что уже готово в проекте

* `next.config.ts` — заголовки безопасности и кэш для картинок. Раньше они
  жили в `netlify.toml`; перенесены в конфиг самого Next.js, чтобы работать
  одинаково на любой платформе и при локальном `next start`.
* `.nvmrc` — фиксирует Node 22.
* Никаких файлов конфигурации хостинга не нужно: Vercel определяет Next.js сам.

## Вариант 1. Через командную строку — так сделано сейчас

### Шаг 1. Войти

```bash
npx vercel login
```

Команда покажет ссылку и код вида `HJDN-NGFT`. Откройте ссылку в браузере,
подтвердите код — терминал сам продолжит работу.

Если аккаунта Vercel нет, сначала зарегистрируйтесь на vercel.com кнопкой
**Continue with GitHub** и выберите бесплатный тариф **Hobby**. Попытка войти
без регистрации даёт ошибку `account_not_found`.

### Шаг 2. Создать проект

```bash
cd Electric_Fireplaces
npx vercel link --yes --project studiya-kaminov
```

### Шаг 3. Указать адрес сайта

```bash
printf 'https://studiya-kaminov.vercel.app' | \
  npx vercel env add NEXT_PUBLIC_SITE_URL production --visibility config --no-sensitive
```

Флаги `--visibility config --no-sensitive` обязательны: переменные с префиксом
`NEXT_PUBLIC_` попадают в браузерный код, поэтому Vercel запрещает помечать их
секретными и без этих флагов возвращает `invalid_visibility`.

### Шаг 4. Опубликовать

```bash
npx vercel deploy --prod
```

Сборка идёт на стороне Vercel, занимает около минуты. В конце команда печатает
адрес.

## Вариант 2. Автодеплой из GitHub

Чтобы каждый `git push` в `main` сам пересобирал сайт, нужно установить
приложение Vercel в GitHub-аккаунт. Из командной строки это сделать нельзя —
`npx vercel git connect` вернёт `Failed to connect ... to project`, пока
приложения нет.

1. Открыть https://vercel.com/devgreenbox/studiya-kaminov/settings/git
2. **Connect Git Repository** → **GitHub**
3. GitHub предложит установить приложение Vercel — дать доступ к репозиторию
   `studiya-kaminov` (можно только к нему, не ко всем)
4. Выбрать репозиторий в списке и подтвердить

После этого команда `npx vercel deploy --prod` больше не нужна — достаточно
`git push`.

## Переменные окружения

Обязательная одна:

| Переменная | Значение | Зачем |
|---|---|---|
| `NEXT_PUBLIC_SITE_URL` | `https://studiya-kaminov.vercel.app` | canonical, OpenGraph, `sitemap.xml` |

Остальные добавляются, когда заказчик передаст доступы. Пока их нет, сайт
работает на демонстрационных провайдерах и честно сообщает об этом в интерфейсе.

**Доставка.** Перевозчиков два: СДЭК (основной) и «Деловые Линии»
(дополнительный). Подключаются независимо — можно начать с одного.

| Переменная | Значение |
|---|---|
| `DELIVERY_ORIGIN_CITY` | город отправления, например `Москва` |
| `CDEK_API_URL` | `https://api.cdek.ru` |
| `CDEK_ACCOUNT` | идентификатор клиента из личного кабинета СДЭК |
| `CDEK_SECURE_PASSWORD` | пароль интеграции СДЭК |
| `DELLIN_API_URL` | `https://api.dellin.ru` |
| `DELLIN_APP_KEY` | ключ из личного кабинета «Деловых Линий» |
| `DELLIN_SESSION_ID` | идентификатор сессии |

Переменную `DELIVERY_PROVIDER` со значением `mock` нужно удалить, иначе расчёт
останется демонстрационным даже с заполненными ключами.

**Письма:**

| Переменная | Значение |
|---|---|
| `EMAIL_TRANSPORT` | `smtp` |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASSWORD` | доступы почты |
| `EMAIL_FROM` | адрес отправителя |
| `EMAIL_SHOP` | куда приходят заказы и заявки |

Перед включением `EMAIL_TRANSPORT=smtp` нужно доустановить `nodemailer` и
раскомментировать отправку в `src/lib/notifications/email/smtp-transport.ts` —
подробности в `README.md`.

Добавляются в **Settings → Environment Variables** или командой
`npx vercel env add ИМЯ production`. Эти переменные серверные, префикса
`NEXT_PUBLIC_` у них нет, поэтому дополнительные флаги не нужны.

> Ключи задаются **только** в панели Vercel. В репозиторий `.env.local` не
> коммитится, во frontend-бандл секреты не попадают.

**Любая правка переменной применяется только после пересборки** —
`npx vercel deploy --prod` или **Redeploy** в панели.

## Что проверить после деплоя

1. Открыть `/` — логотип, фотографии и анимация огня на первом экране.
2. Открыть `/catalog?category=uglovye` — фильтр должен примениться сразу из URL.
3. Открыть `/sitemap.xml` — внутри должен быть боевой домен, а не `localhost`.
   Если `localhost` — значит не задан `NEXT_PUBLIC_SITE_URL` или не была
   сделана пересборка.
4. Открыть `/robots.txt` — там же должен быть боевой домен.
5. Добавить товар в корзину, применить промокод `FIRE10`, рассчитать доставку —
   должны появиться обе компании с ценой и сроком — и оформить тестовый заказ
   до страницы `/order/success` с накладной.

## Защита сайта паролем

Боевой адрес открыт всем без пароля. Если сайт нужно временно закрыть от
посторонних до сдачи заказчику: **Settings** → **Deployment Protection** →
**Vercel Authentication** или **Password Protection**.

Учтите: часть вариантов защиты доступна только на платном тарифе. Превью-сборки
(всё, что не `--prod`) по умолчанию и так закрыты от посторонних.

## Ограничение на бесплатном хостинге

Заказы сохраняются в памяти серверной функции (`src/lib/orders/store.ts`).
Функции живут недолго и не делят память между собой, поэтому **история заказов
не накапливается**: заказ создаётся, письма уходят, покупатель видит страницу
успеха и накладную — но получить старый заказ по номеру через сервер нельзя.

Для демонстрации и передачи заказчику этого достаточно. Когда понадобится
история — подключите базу или CRM: нужно написать один класс с методами `save`
и `find` и вернуть его из `getOrderStore()`. Остальной код менять не придётся.

## Свой домен

**Settings** → **Domains** → **Add**. Vercel покажет, какие DNS-записи
прописать у регистратора, и сам выпустит бесплатный SSL-сертификат.

После подключения домена поменяйте `NEXT_PUBLIC_SITE_URL` на новый адрес и
сделайте пересборку — иначе canonical и `sitemap.xml` останутся на прежнем.

## Если сборка упала

1. Панель → **Deployments** → нажать на неудачный деплой → лог сборки.
2. Частые причины:
   * не установлены зависимости — проверьте, что `package-lock.json` в
     репозитории;
   * ошибка типов или линтера — воспроизводится локально командами
     `npm run typecheck` и `npm run lint`;
   * нехватка памяти на больших сборках — переменная окружения
     `NODE_OPTIONS` со значением `--max-old-space-size=4096`.
3. Локальная проверка ровно той же сборки:

```bash
npm ci
npm run build
npx next start
```

## Проверка боевого сайта тестами

Тесты можно прогнать не по локальной сборке, а прямо по развёрнутому адресу:

```bash
E2E_BASE_URL=https://studiya-kaminov.vercel.app npm run test:e2e
```

Это самая надёжная проверка после деплоя: она проходит весь путь покупки —
каталог, фильтры, поиск, избранное, корзина, промокод, расчёт доставки,
оформление заказа и накладную.
