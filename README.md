# Студия каминов — сайт производителя электрокаминов

Многостраничный интернет-магазин на Next.js: каталог, поиск, фильтры, избранное,
корзина, промокоды, расчёт доставки, оформление заказа и накладная.

Название и логотип взяты из брифа заказчика, каталог собран из материалов с
Яндекс.Диска (архив «Для сайта.rar»).

---

## Быстрый старт

```bash
npm install
cp .env.example .env.local   # при необходимости
npm run dev                  # http://localhost:3000
```

Другие команды:

```bash
npm run build      # production-сборка
npm run start      # запуск собранного приложения
npm run lint       # ESLint
npm run typecheck  # проверка типов TypeScript
npm run test:e2e   # e2e-тесты Playwright (сами поднимут сборку)
```

Требуется Node.js 20+.

---

## Стек

- Next.js 16 (App Router) + React 19
- TypeScript (strict)
- Tailwind CSS 4 — токены дизайна в `src/app/globals.css`
- Zustand с persist — корзина и избранное переживают перезагрузку
- Иконки — свои, «от руки»: готовые SVG-пути, библиотек в браузер не уезжает

Тяжёлых зависимостей нет: карусель, модальные окна, drawer, галерея и
уведомления написаны на месте.

## Подключение боевых интеграций

Внешние сервисы спрятаны за интерфейсами, поэтому интерфейс сайта работает уже
сейчас, а боевой API подключается без переписывания страниц:

```text
UI → сервисный интерфейс → mock-адаптер → боевой адаптер
```

### Доставка: СДЭК и «Деловые Линии»

Перевозчики заданы в `src/config/site.ts` → `carriers`. СДЭК помечен
`primary: true` — он выбран по умолчанию, «Деловые Линии» идут дополнительным
вариантом. Покупатель выбирает компанию при оформлении заказа: сайт считает обе
сразу и показывает цену и срок рядом.

- Интерфейс: `DeliveryProvider` в `src/types/index.ts`
- Выбор провайдера по перевозчику: `src/lib/delivery/index.ts`
- Демо-расчёт: `src/lib/delivery/mock-provider.ts` — прозрачная формула по весу,
  объёму, габаритам и зоне доставки, с разными коэффициентами для компаний;
  результат всегда помечен как предварительный (`isEstimate: true`)
- Боевые адаптеры: `src/lib/delivery/cdek-provider.ts` и
  `src/lib/delivery/dellin-provider.ts`

Чтобы включить боевой расчёт, заполните ключи нужной компании в `.env.local` и
уберите `DELIVERY_PROVIDER=mock`. Компании подключаются независимо: если есть
ключи только СДЭК, «Деловые Линии» продолжат считаться демо-расчётом. Пока
ключей нет, работают обе на mock-провайдере, и кнопка расчёта не «мёртвая».

Чтобы добавить третью компанию: допишите её в `carriers`, добавьте профиль в
`CARRIER_PROFILE` mock-провайдера и, при наличии API, свой адаптер. Интерфейс
подхватит её сам — и на странице оформления, и на `/delivery`.

### Уведомления на почту

- Интерфейс: `EmailTransport` в `src/lib/notifications/email/types.ts`
- Выбор транспорта: `src/lib/notifications/email/index.ts`
- Режим разработки: `console-transport.ts` — письмо печатается в терминал
- Боевой транспорт: `smtp-transport.ts` — заготовка; поставьте `nodemailer`
  и раскомментируйте отправку, затем задайте `EMAIL_TRANSPORT=smtp`

Письма отправляются в двух местах: при создании заказа (магазину и покупателю) и
при отправке формы «Связаться с продавцом».

### Хранилище заказов

`src/lib/orders/store.ts` — интерфейс `OrderStore` с реализацией в памяти
процесса. Чтобы подключить БД или CRM, напишите класс с методами `save` и `find`
и верните его из `getOrderStore()`. API-роуты, письма и страница успеха менять не
нужно.

Личный кабинет, СДЭК PAY, МойСклад/1С, Telegram-бот и CRM в брифе не выбраны и
намеренно не реализованы, но модель заказа (`Order` в `src/types/index.ts`)
рассчитана на их подключение.

## Иконки

Все иконки на сайте выглядят нарисованными от руки — требование заказчика.

Рисовать полсотни иконок вручную значило бы недели работы и неизбежный
разнобой в почерке. Вместо этого геометрия прогоняется через **rough.js** —
библиотеку, которая имитирует рисунок от руки: каждая линия проводится дважды
с лёгким промахом, прямые выгибаются, углы перелетают.

```bash
npm run icons     # пересобрать src/components/icons/sketch-paths.json
```

Скрипт `scripts/make-sketch-icons.mjs` работает на этапе сборки, в браузер
rough.js не попадает — там только готовые пути. Результат детерминирован:
у каждой иконки свой seed, поэтому повторный запуск даёт файл байт в байт.

Два набора:

| Компонент    | viewBox | Где                                             | Откуда геометрия             |
| ------------ | ------- | ----------------------------------------------- | ---------------------------- |
| `SketchIcon` | 24      | интерфейс: корзина, поиск, стрелки, галочки     | lucide-react (ISC)           |
| `PencilIcon` | 48      | информационные блоки: производство, шаги заказа | свои контуры в скрипте       |
| `LineIcon`   | 24      | только шапка сайта                              | lucide-react, без огрубления |

`LineIcon` — ровное начертание по просьбе заказчика: шапка висит поверх любой
страницы, и в мелком кегле рядом с логотипом дрожащий контур читается как
дефект печати, а не как приём. Геометрия та же, отличается только обводка.

`lucide-react` осталась в проекте как **devDependency**: она нужна только
скрипту как источник геометрии. Версия закреплена — в 1.x структура пакета
другая, и разбор сломается.

**Про настройку.** Рисунок от руки дают не смещения точек, а выгиб линий.
`maxRandomnessOffset` дёргает концы отрезков; на иконке 24×24 внутренние
детали занимают 3–4 единицы, и смещение на 2 их попросту стирает — получается
клякса. `bowing` выгибает линию между концами, не трогая сами концы: структура
цела, а прямых не остаётся ни одной. Поэтому bowing высокий, offset низкий.

Добавить иконку: вписать её в `ui` (имя экспорта lucide) или `decorative`
(свои контуры) в скрипте и запустить `npm run icons`.

## Изображения

### Откуда взяты

Все фотографии товаров — из материалов заказчика: архив `Для сайта.rar` по
ссылке `https://disk.yandex.ru/d/uPvtY3zkN94mQg`. Фотографии конкурентов и
сгенерированные изображения не используются.

### Как пересобрать

```bash
# 1. распакуйте архив так, чтобы внутри лежала папка «Для сайта»
node scripts/prepare-images.mjs /путь/к/распакованному/архиву

# 2. обложки категорий, баннеры карусели и кадры для блока о производстве
node scripts/make-covers.mjs
```

Второй скрипт работает уже с готовыми WebP из `public/images/products`, поэтому
запускать его можно и без исходного архива — например, чтобы поменять кадр в
обложке категории.

**Фотографии от заказчика вне архива** кладутся в
`incoming/products/<slug>/<NN>.<ext>` и подменяют кадр с этим номером. Архив
остаётся источником по умолчанию, поэтому пересборка не затирает присланное
обратно архивным. Подробности — в `incoming/README.md`.

Скрипт берёт **только** те файлы, которые перечислены в
`scripts/image-manifest.json`, приводит их к WebP и единым пропорциям (товары —
3:4, категории — 4:3) и обновляет `src/data/image-index.json`.

Размер работает **потолком, а не целью**: `withoutEnlargement` не даёт
увеличивать кадр. Материалы разного размера — большинство 1024×1365, часть
крупнее (до 2767×3689), часть заметно мельче, вплоть до 550×733. Раньше все они
приводились к 1050×1400, и мелкие растягивались почти вдвое — отсюда было мыло
на карточках товара.

`image-manifest.json` — это ручная кураторская раскладка: для каждого товара
задан порядок кадров, первым идёт самый «чистый» кадр без маркетплейс-надписей,
дальше идут инфографика с габаритами, режимами работы и упаковкой. Чтобы
поменять главное фото товара — переставьте файл в начало списка и перезапустите
скрипт.

`scripts/make-covers.mjs` собирает производные изображения: обложки категорий
(4:3), баннеры карусели (4:5), кадры для блока о производстве и главные фото
карточек. Для каждого задан кадр-источник и окно кадрирования — так камины
стоят по центру, в одном масштабе, а маркетплейс-надписи остаются за рамкой.
Правится в одном месте, в объектах `COVERS`, `PROMOS`, `PRODUCTION` и `CARDS`.

Про `CARDS` отдельно: у пяти моделей — «Честер», «Мальта угловая», «Верона»,
«Мальта венге» и «Дублин Премиум» — среди исходников нет ни одного пригодного
кадра без надписей.
Для них вырезается середина кадра, без текстовых полос сверху и снизу.
Результат ложится в `public/images/cards/` и становится первым фото галереи:
именно он показывается в каталоге и как главное фото на странице товара.
Исходник остаётся дальше в галерее как инфографика с габаритами.

Если заказчик пришлёт чистую съёмку — уберите модель из `CARDS`, положите
фотографию в исходники и переставьте её первой в `image-manifest.json`.

### Фотографии с надписями

Часть исходных фотографий — карточки для маркетплейсов с наложенным текстом
(название модели, габариты, режимы работы, упаковка). Для каждого товара в
`image-manifest.json` первым выбран самый чистый кадр, а инфографика убрана в
конец галереи, где она полезна как справка по характеристикам.

У четырёх моделей чистого кадра в материалах нет вообще — для них главное фото
получается кадрированием (см. `CARDS` выше). Ни в каталоге, ни на страницах
товаров надписей на главных фотографиях не остаётся.

### Что осталось заглушкой

| Где                                      | Что нужно                |
| ---------------------------------------- | ------------------------ |
| Главная, блок «Собственное производство» | фотография цеха и сборки |
| `/about`, блок контроля качества         | съёмка производства      |

Заглушки визуально помечены как заглушки (компонент `PlaceholderImage`) и не
выдают себя за настоящие фотографии. Готовые фото кладутся в
`public/images/production/` и подставляются вместо `<PlaceholderImage>` в
`src/components/home/ProductionBlock.tsx` и `src/app/about/page.tsx`.

### Анимация огня на первом экране

В материалах видео нет, поэтому пламя на реальной фотографии горящего очага
оживляется лёгкой CSS-анимацией — без тяжёлого JS. Позиция свечения задана в
`src/config/site.ts` → `heroMedia.flame`.

Когда появится ролик: положите его в `public/video/`, укажите путь в
`heroMedia.video` — компонент сам переключится на
`<video autoplay muted loop playsInline>` с постером из hero-фотографии.
Анимация уважает `prefers-reduced-motion`.

## Данные, которые требуют подтверждения заказчиком

Ниже — всё, чего в исходных материалах не было или что в них противоречит само
себе. Ничего из этого не выдумано: спорные места вынесены в интерфейс (плашка
«Требует подтверждения» на странице товара) и в конфиги.

**Цены.** Прайса в материалах нет — ни таблиц, ни PDF. Все цены в
`src/data/prices.ts` демонстрационные и помечены как таковые. Это единственное
место, где заданы цены.

**Контакты.** Телефон, email, адрес, время работы, мессенджеры и соцсети в
материалах отсутствуют. Заполнены нейтральными значениями в
`src/config/site.ts` с пометкой `PLACEHOLDER`.

**Реквизиты и юридическое наименование.** Не предоставлены — `legal.requisites`
в `src/config/site.ts`.

**Способы оплаты.** В брифе не указаны. На странице `/delivery` стоит
нейтральный текст с явной пометкой.

**Отзывы.** Реальных нет. В `src/data/reviews.ts` три демонстрационные карточки
с флагом `demo: true`; в интерфейсе раздел честно подписан как
демонстрационный.

**Названия «Версаль» и «Верона».** В материалах эти классические камины лежат в
папке «Версаль», при этом в обоих текстовых описаниях модель названа «Верона», а
на фотографии варианта «слоновая кость» — «VERSAL». По решению заказчика они
разведены как две модели: белая — «Верона», слоновая кость — «Версаль».
Требуется финальное подтверждение.

**Честер, диагональ телевизора.** В описании — до 65″, на инфографике — до 75″.
На сайте оставлено значение из описания.

**Мощность обогрева.** В описаниях указано 750/1500 Вт, на одной инфографике —
900/1500 Вт. Использованы значения из описаний.

**Модель «Модерн».** В материалах есть только фотографии: нет описания,
габаритов, модели очага и мощности. Характеристики заполнены по фотографиям и
помечены как требующие дополнения.

**«Дублин Премиум».** Текстового описания нет; характеристики собраны с
инфографики производителя, описание написано по фотографиям — нужна вычитка.

**Вес изделий.** Не указан. Для предварительного расчёта доставки вес
оценивается по габаритам и усреднённой плотности
(`src/lib/orders/shipment.ts`). Когда появятся реальные веса — добавьте поле
`weight` в товар, тип это уже допускает.

```text
/favorites            избранное

/checkout             оформление заказа
/order/success        заказ оформлен + накладная
/about                о компании и производстве
/reviews              отзывы
/delivery             оплата и доставка
/contacts             контакты
/privacy              политика конфиденциальности
```

API: `POST /api/delivery/calculate`, `POST /api/contact`, `POST /api/orders`.

Состояние каталога живёт в URL: ссылка
`/catalog?category=uglovye&sort=price-asc` открывает нужную выборку.

## Накладная

После оформления заказа на `/order/success` формируется документ с номером
заказа, датой, данными покупателя, составом, скидкой, доставкой и итогом.
Печатается штатным диалогом браузера — оттуда же сохраняется в PDF. Отдельная
PDF-библиотека не подключалась: она добавила бы вес, не давая ничего сверх
этого.

## Тесты

```bash
npx playwright install chromium   # один раз
npm run test:e2e                  # 38 тестов: desktop + mobile
```

Playwright сам собирает проект и поднимает сервер на порту 3100 — отдельно
запускать `npm run build` не нужно.

`e2e/shop.spec.ts` проверяет критические сценарии из ТЗ:

- главная → каталог;
- фильтр по категории и его отражение в URL;
- сортировка по цене;
- пустая выдача и сброс фильтров;
- поиск и переход в найденный товар;
- избранное, в том числе сохранение после перезагрузки;
- корзина: добавление, изменение количества, промокод, удаление;
- ошибка при неверном промокоде;
- оформление заказа: расчёт доставки, валидация согласия, накладная;
- форма «Связаться с продавцом»;
- страница 404;
- отсутствие горизонтального скролла на всех основных страницах.

## Доступность и SEO

- Семантическая разметка, корректная иерархия заголовков, `alt` у изображений
- `aria-label` у кнопок-иконок, связь ошибок с полями через `aria-describedby`

- Уникальные `title`, `description`, `canonical` и OpenGraph на каждой странице
- JSON-LD `Product` и `BreadcrumbList` на страницах товаров, `Organization` на контактах
- `sitemap.xml` и `robots.txt` генерируются автоматически
- Служебные страницы (корзина, оформление, поиск, избранное) закрыты от индексации
